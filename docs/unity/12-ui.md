# UI: UI Toolkit против uGUI, HUD автомобиля

Что выбрать под интерфейс проекта, как собрать спидометр/тахометр/мини-карту и где UI начинает жрать кадры. Заглядывать перед первой строчкой UI-кода и когда HUD начнёт тормозить.

---

## TL;DR — решения для нашего проекта

1. **Весь UI делаем на UI Toolkit** — HUD, меню, настройки, отладка. Решающий для нас аргумент не производительность, а формат: `.uxml`/`.uss` — это обычный текст, который читается в diff и мержится, в отличие от `.prefab` (YAML со ссылками по GUID), который я не могу править надёжно.
2. **Знай контраргумент.** В документации Unity 6.3 официальная рекомендация для **рантайма всё ещё uGUI**, а UI Toolkit проходит как «альтернатива» ([Comparison of UI systems](https://docs.unity3d.com/6000.3/Documentation/Manual/UI-system-compare.html)). Это не «UI Toolkit сырой» — это осторожность Unity. Но если наткнёмся на дырку (см. раздел 2), знаем, чем платим.
3. **Спидометр и тахометр — кастомный `VisualElement` с Painter2D** (Vector API: рисование дуг/линий кодом в `generateVisualContent`). Никаких спрайтов с `fillAmount` и заранее нарезанных шкал.
4. **Стрелка — `style.rotate` + `transform-origin`**, элементу выставить `usageHints = UsageHints.DynamicTransform`. Никогда не анимировать `width`/`top`/`left` — это пересчёт лэйаута каждый кадр.
5. **Текст цифр обновлять только при смене целого значения** и брать из заранее посчитанного массива строк. `label.text = $"{speed:0}"` каждый кадр — это мусор для GC.
6. **Мини-карта — вторая ортографическая камера → RenderTexture → `Background.FromRenderTexture()`** в фоне `VisualElement`. Это единственный рабочий путь: 3D-объекты внутрь UI Toolkit вставить нельзя, поддержка числится лишь среди кандидатов на период после 6.7.
7. **Runtime data binding — только для «медленных» экранов** (настройки, статистика, экран паузы). Для HUD на 60 Гц связывание избыточно: проще и дешевле руками писать в закешированные элементы.
8. **Ввод: ничего не настраивать.** Пока в сцене нет uGUI, UI Toolkit сам подхватывает Input System через свой встроенный event system. `EventSystem` + `InputSystemUIInputModule` нужны только если смешаем две системы.
9. **Сразу включить ATG** (Advanced Text Generator) — `Edit > Project Settings > UI Toolkit > Enable Advanced Text Generator`. В 6.3 он опционален, с 6.5 станет умолчанием; даёт 10–40 % CPU и нормальный Unicode.
10. **Одна `PanelSettings` на HUD**, Scale Mode = `Scale With Screen Size`, Reference Resolution 1920×1080, Match 0.5. Несколько `UIDocument` могут ссылаться на неё же — это дешевле, чем несколько панелей.

## 1. Что такое UI Toolkit в терминах, которые нам нужны

| Термин | Что это | Аналог в uGUI |
|---|---|---|
| `UIDocument` | MonoBehaviour-мост между сценой и UI-деревом | `Canvas` |
| `PanelSettings` | ассет с настройками рендера панели: масштаб, sort order, атлас | `Canvas Scaler` + настройки `Canvas` |
| UXML | XML-разметка иерархии элементов (текстовый файл) | иерархия GameObject в префабе |
| USS | стили в духе CSS: селекторы, классы, наследование | ничего, стилей в uGUI нет |
| `VisualElement` | узел дерева, **не** GameObject и **не** MonoBehaviour | `RectTransform` + компоненты |
| visual tree | всё дерево элементов, живёт в памяти, не видно в Hierarchy | иерархия сцены |
| UI Builder | визуальный редактор UXML/USS внутри Unity | редактирование префаба в сцене |

Ключевое следствие: **прямую ссылку на элемент из инспектора не протянуть.** Элементы ищутся в рантайме: `root.Q<Label>("speed-value")`. Ссылки «стрингово-типизированные», опечатка даёт `null` без ошибки компиляции. Возможность ссылаться на элементы UXML из MonoBehaviour Unity держит в активной разработке с прицелом на 6.7 — сейчас её нет.

## 2. Состояние UI Toolkit в Unity 6.x: что готово и чего нет

### Что появилось по версиям (по официальному апдейту команды UI Toolkit, декабрь 2025)

| Фича | Версия | Комментарий |
|---|---|---|
| Runtime data binding | 6.0 | связывание свойств элемента с данными без ручных апдейтов |
| `[UxmlElement]` / `[UxmlAttribute]` | 6.0 | пришли на смену `UxmlFactory`/`UxmlTraits` (те помечены устаревшими) |
| `TabView`, `ToggleButtonGroup`, иконки у `Button`, `Slider.fill` | 6.0 | доступны и в рантайме |
| Advanced Text Generator (ATG) | 6.0 (opt-in) | HarfBuzz + ICU + FreeType, RTL и полный Unicode |
| `TextElement.PostProcessTextVertices` | 6.2 (версия не подтверждена официально) | доступ к квадам глифов, кастомная анимация текста; в 6.3 API присутствует |
| **World-space UI** | **6.2** | `PanelSettings.Render Mode = World Space` |
| Импорт и рендер SVG (UI Toolkit Vector Image) | 6.3 | резкая графика на любом разрешении |
| Кастомные шейдеры через Shader Graph (UI target, нода Render Type Branch) | 6.3 | **только URP** |
| USS-фильтры: `blur`, `grayscale`, `invert`, `opacity`, `sepia`, `tint`, `hue-rotate`, `contrast` | 6.3 | пост-обработка поддерева элементов |
| UI Test Framework (пакет `com.unity.ui.test-framework`) | 6.3 | автотесты UI в CI |
| ATG по умолчанию в редакторе | 6.3 | в рантайме — с 6.5, но все фичи 6.5 забэкпорчены в 6.3 |

### Чего в 6.3 всё ещё нет (из того же официального апдейта — это список «что приоритизировать»)

- Мягкие маски (soft masking).
- **Партиклы и 3D-объекты внутри UI.**
- CSS Grid, `z-index`, `gap`, media queries, псевдоклассы `:first-child` / `:nth-child`, единицы `vh`/`vw`, `em`/`rem`.
- Поддержка Addressables / Asset Bundles для UXML/USS; API загрузки UXML/USS в рантайме.
- Биндинг событий прямо в UXML; биндинг не-атрибутов (`itemsSource`); нормальный workflow биндинга `ListView`.
- Импорт из Figma.
- Из USS-фильтров **не поддержан `drop-shadow`** (в отличие от CSS). Градиенты и тени как обычные USS-свойства — в активной разработке.

### Асимметрия возможностей (таблица из документации 6.3)

**Только у uGUI:** авторинг прямо в сцене, сериализованные события (`UnityEvent` в инспекторе), интеграция с Animation Clips и Timeline.

**Только у UI Toolkit:** data binding, USS-переходы, динамический атлас текстур, сглаживание UI, RTL и эмодзи, SVG, глобальное управление стилями, гибкий flex-лэйаут.

**У обоих:** world-space рендер, кастомные материалы и шейдеры, маски, спрайт-атласы, поддержка Input System.

Для нас критично только одно: **анимировать UI из Timeline нельзя.** Если понадобится кат-сцена, где HUD выезжает по ключам аниматора — это придётся делать кодом. Всё остальное закрывается USS-переходами.

## 3. Версионирование в git — почему это перевешивает

- UXML и USS — текст. `git diff` читается человеком, конфликты решаются руками.
- Официальная документация прямо отмечает: правка биндингов руками в UXML даёт «более понятные диффы для контроля версий».
- `.prefab` с uGUI-иерархией — YAML с `fileID`/`guid`; изменение порядка двух кнопок переставляет блоки по всему файлу.
- **Обратная сторона:** динамические font asset'ы (TextCore/TMP) генерируют бинарные данные атласа и шумят в истории. Инженер Unity рекомендует в UI Toolkit по возможности назначать **обычный Unity `Font`** вместо генерируемого Font Asset — тогда версионируется только сам `.ttf`.
- И `.uxml`, и `.uss`, и `.asset` (PanelSettings) обязаны попадать в коммит вместе с `.meta`.

## 4. HUD: спидометр и тахометр

### Дуга шкалы — Painter2D, а не спрайты

Кастомный контрол рисует дугу кодом: масштабируется на любое разрешение без ассетов и без атласа.

```csharp
using UnityEngine;
using UnityEngine.UIElements;

[UxmlElement]                       // с Unity 6: класс обязан быть partial
public partial class GaugeArc : VisualElement
{
    static readonly CustomStyleProperty<Color> k_TrackColor = new("--track-color");
    static readonly CustomStyleProperty<Color> k_FillColor  = new("--fill-color");

    Color _track = Color.gray, _fill = Color.red;
    float _normalized;

    [UxmlAttribute]                 // редактируется в UI Builder
    public float normalized
    {
        get => _normalized;
        set { _normalized = Mathf.Clamp01(value); MarkDirtyRepaint(); }
    }

    public GaugeArc()
    {
        generateVisualContent += OnGenerate;
        RegisterCallback<CustomStyleResolvedEvent>(_ => ResolveColors());
    }

    void ResolveColors()
    {
        var dirty  = customStyle.TryGetValue(k_TrackColor, out _track);
        dirty     |= customStyle.TryGetValue(k_FillColor,  out _fill);
        if (dirty) MarkDirtyRepaint();
    }

    void OnGenerate(MeshGenerationContext ctx)
    {
        var p      = ctx.painter2D;                    // Vector API
        var rect   = contentRect;
        var radius = Mathf.Min(rect.width, rect.height) * 0.5f - 8f;
        const float start = 135f, sweep = 270f;        // 0° — вправо, положительные по часовой

        p.lineWidth = 12f;
        p.lineCap   = LineCap.Butt;

        p.strokeColor = _track;
        p.BeginPath();
        p.Arc(rect.center, radius, start, start + sweep);
        p.Stroke();

        p.strokeColor = _fill;
        p.BeginPath();
        p.Arc(rect.center, radius, start, start + sweep * _normalized);
        p.Stroke();
    }
}
```

Цвета задаются в USS через кастомные свойства — трек и заливка настраиваются без перекомпиляции:

```css
.gauge { --track-color: rgb(60, 60, 65); --fill-color: rgb(255, 96, 32); width: 240px; height: 240px; }
.gauge--redline { --fill-color: rgb(220, 30, 30); }
```

Переключение «в красной зоне» — это `AddToClassList("gauge--redline")`, а не пересборка меша.

### Стрелка

```csharp
_needle.usageHints = UsageHints.DynamicTransform;   // выставить ДО добавления в панель
// каждый кадр:
float deg = Mathf.Lerp(startDeg, endDeg, rpm01);
_needle.style.rotate = new StyleRotate(new Rotate(new Angle(deg, AngleUnit.Degree)));
```

В USS у стрелки `transform-origin: 50% 90%;` — точка вращения у основания. Порядок трансформаций фиксирован: scale → rotate → translate. Сглаживание делаем в C# (`Mathf.SmoothDamp` по значению), а не USS-переходом: переход будет перезапускаться на каждое новое значение.

### Цифры без аллокаций

`TextElement.text` принимает только `string`, no-alloc сеттера (как `TMP_Text.SetText(char[])` в uGUI) в UI Toolkit нет. Поэтому строки готовим заранее и пишем только при смене целого значения:

```csharp
static readonly string[] k_Kmh = BuildStrings(400);   // один раз, статически
int _lastKmh = -1;

void UpdateSpeed(float speedKmh)
{
    int kmh = Mathf.Clamp(Mathf.RoundToInt(speedKmh), 0, k_Kmh.Length - 1);
    if (kmh == _lastKmh) return;        // 99% кадров выходим здесь
    _lastKmh = kmh;
    _speedLabel.text = k_Kmh[kmh];      // строка из кеша, без new
}
```

### Где обновлять

Источник данных обновляется в `FixedUpdate` (физика), сам UI трогаем в `Update`/`LateUpdate` — визуал не должен зависеть от шага физики. Для второстепенных показаний (температура, передача, топливо) вместо `Update` удобен планировщик UI Toolkit: `root.schedule.Execute(RefreshSecondary).Every(100);` — раз в 100 мс.

## 5. Мини-карта

1. Вторая камера: `Projection = Orthographic`, смотрит вниз, `Culling Mask` — только слой `Minimap`, `Target Texture` = наш `RenderTexture` (например 256×256).
2. Фон элемента в UI Toolkit: `_minimap.style.backgroundImage = new StyleBackground(Background.FromRenderTexture(_minimapRT));`
3. Круглая маска — `border-radius: 50%`. Важно: скруглённые углы и сложные маски идут через **stencil buffer** и рвут батчинг (до 7 уровней вложенности). Прямоугольная маска — шейдерная, батч не ломает. Для одной мини-карты это копейки, но не увлекаться.
4. Иконка машины — отдельный `VisualElement` с `rotate` по yaw машины, ему `usageHints = UsageHints.DynamicTransform`.

Цена мини-карты — это **вторая камера и лишний проход рендера**, а не UI. Если станет дорого: рендерить не каждый кадр (дёргать `camera.enabled` по расписанию) либо резать разрешение RT.

## 6. Индикаторы, экран настроек, отладочные оверлеи

- **Линейные индикаторы** (топливо, буст, нитро): `Slider` с `fill = true` (Unity 6) или `ProgressBar`, либо просто `VisualElement` с анимируемым `scale`. Не `width` — это лэйаут.
- **Экран настроек**: `TabView` + `Toggle`, `SliderInt`, `DropdownField`. Здесь runtime data binding уместен: источником делаем `ScriptableObject`-конфиг, и UI сам подхватывает значения.
- **Отладочные оверлеи**: отдельный `UIDocument` со своей `PanelSettings` и бо́льшим `Sort Order`, включается по клавише. `OnGUI`/IMGUI не использовать — он аллоцирует каждый кадр и это legacy-система, предназначенная для редактора.

Источник данных для биндинга (паттерн из документации 6.3):

```csharp
using System;
using Unity.Properties;
using UnityEngine;
using UnityEngine.UIElements;

[CreateAssetMenu(menuName = "Config/Vehicle Settings"), GeneratePropertyBag]
public class VehicleSettings : ScriptableObject, INotifyBindablePropertyChanged
{
    [SerializeField, DontCreateProperty] float _maxSpeed = 220f;

    public event EventHandler<BindablePropertyChangedEventArgs> propertyChanged;

    [CreateProperty]                       // без этого — рефлексия в рантайме
    public float MaxSpeed
    {
        get => _maxSpeed;
        set
        {
            _maxSpeed = value;
            propertyChanged?.Invoke(this, new BindablePropertyChangedEventArgs(nameof(MaxSpeed)));
        }
    }
}

// Привязка из кода:
label.SetBinding("text", new DataBinding
{
    dataSourcePath = new PropertyPath(nameof(VehicleSettings.MaxSpeed)),
    bindingMode    = BindingMode.ToTarget      // только данные → UI
});
```

Режимы: `TwoWay` (умолчание), `ToTarget`, `ToSource`, `ToTargetOnce`. Для дисплеев всегда `ToTarget` — `TwoWay` по умолчанию означает лишнюю работу.

Гибридный вариант, который стоит взять: в UXML указывать только `data-source-type` и пути, а сам источник назначать в рантайме одной строкой `element.dataSource = mySource;`. Если в UXML прописан конкретный ассет `data-source=`, подменить его в рантайме уже нельзя.

## 7. Ввод, геймпад, фокус

- Пока в сцене **нет** uGUI, UI Toolkit создаёт собственный event system, не привязанный к сцене. Он сам определяет активный backend ввода. `Active Input Handling` в Player Settings ставим `Input System Package (New)`.
- События UI берутся из project-wide actions: `UI/Point`, `UI/Click`, `UI/ScrollWheel`, `UI/Navigate`, `Submit`, `Cancel` → `PointerMoveEvent`, `PointerDownEvent`, `WheelEvent`, `NavigationMoveEvent`, `NavigationSubmitEvent`, `NavigationCancelEvent`.
- Если добавим uGUI (например, чужой ассет), нужны `EventSystem` + `InputSystemUIInputModule`. Тогда UI Toolkit создаёт мосты `PanelRaycaster` и `PanelEventHandler`, а собственная обработка ввода отключается.
- Фокус: порядок обхода по умолчанию — DFS по дереву; `tabIndex > 0` двигает элемент вперёд, `tabIndex < 0` выкидывает из навигации; `delegatesFocus` пробрасывает фокус ребёнку; `Focus()` / `Blur()`.
- **Слабое место**, о котором стабильно пишут в официальной теме: явно задать «из этой кнопки вправо — вон та» как в uGUI нельзя, фокусное кольцо считается автоматически. Для экрана настроек с одноколоночным списком это не проблема; для сложной раскладки придётся ловить `NavigationMoveEvent` и вызывать `Focus()` руками.

## 8. Масштабирование под разрешения

`PanelSettings > Scale Mode`:

- **Scale With Screen Size** — наш выбор. `Reference Resolution` 1920×1080, `Screen Match Mode = Match Width Or Height`, `Match = 0.5`.
- **Constant Pixel Size** — фиксированный размер в пикселях; для отладочного оверлея это как раз то, что нужно.
- **Constant Physical Size** — по DPI, актуально для мобилок.

Практика: в USS для HUD опираться на проценты и flex, `position: absolute` использовать точечно (стрелка внутри циферблата). Единиц `vw`/`vh` в 6.3 нет. `Sort Order` на `PanelSettings` определяет порядок панелей, `UIDocument.sortingOrder` — порядок документов внутри одной панели.

## 9. Локализация

Пакет `com.unity.localization` (1.5.x) поддерживает UI Toolkit **через систему биндингов, требует Unity 6+**. Даже если сейчас у нас один язык, структура ставится дёшево.

```xml
<ui:Label xmlns:ui="UnityEngine.UIElements" xmlns:l="UnityEngine.Localization">
  <Bindings><l:LocalizedString property="text" table="HUD" entry="gear_reverse" /></Bindings>
</ui:Label>
```

Типы биндингов: `LocalizedString`, `LocalizedTexture`, `LocalizedSprite`, `LocalizedFont`, `LocalizedAudioClip`, `LocalizedGameObject`, `LocalizedMaterial`, `LocalizedMesh`, `LocalizedObject`, `LocalizedTmpFont`. Поле обновляется само при смене локали. В C#: `label.SetBinding("text", new LocalizedString("HUD", "gear_reverse"));`. Для кастомных контролов свойство должно иметь `[UxmlAttribute, CreateProperty]`.

## 10. Производительность UI Toolkit

### Механизмы обновления и их цена

| Что | Когда срабатывает | Цена |
|---|---|---|
| Style resolution | смена класса или стиля | дорого на глубоких деревьях |
| Layout recalculation | смена размера/позиции/выравнивания | дорого, лечится трансформациями |
| Vertex buffer update | смена геометрии (скругления, бордеры) | дорого |
| Render state change | маски, новые текстуры | ломает батчи |

### Батчинг и скрытие

- Один «uber shader» с динамическим ветвлением на все типы отрисовки; поддерживает **до 8 текстур в одном батче**. Девятая — разрыв батча.
- Против разрывов: 2D Sprite Atlas для статики + динамический атлас UI Toolkit (настраивается в `PanelSettings > Dynamic Atlas Settings`, смотреть в Dynamic Atlas Viewer). По умолчанию текстуры крупнее 64×64 в динамический атлас не попадают.
- `Vertex Budget` в `PanelSettings` (по умолчанию 0 = авто): если UI не влезает в один вершинный буфер, Unity создаёт второй и рисует два draw call'а. Проверять во Frame Debugger.

### Анимации

- `translate` / `scale` / `rotate` считаются на GPU и не трогают лэйаут. `width` / `height` / `top` / `left` — трогают.
- `usageHints`: `DynamicTransform` (частые трансформации), `GroupTransform` (родитель кучи `DynamicTransform`-детей), `MaskContainer`, `DynamicColor`, `DynamicPostProcessing`, `LargePixelCoverage`. **Выставлять до добавления элемента в панель** — иначе одноразовый штраф на регенерацию геометрии.
- Не переключать классы на больших поддеревьях во время анимации — это каскад пересчёта стилей.

### Как прятать элементы (по возрастанию эффективности)

| Способ | Рендер | Лэйаут | Когда |
|---|---|---|---|
| `opacity: 0` | идёт | идёт | только для переходов |
| увести за экран | идёт | идёт | почти никогда |
| `visible = false` | нет | идёт | компромисс |
| `style.display = DisplayStyle.None` | нет | нет | частое переключение |
| `RemoveFromHierarchy()` | нет | нет | редкие панели (настройки, пауза) — но всплеск при возврате |

### Оптимизация биндингов, инструменты, что улучшилось

- `[CreateProperty]` на свойстве генерирует код биндинга на этапе компиляции вместо рефлексии в рантайме; `[GeneratePropertyBag]` на типе — то же целиком; `INotifyBindablePropertyChanged` обновляет UI только при реальном изменении; `IDataSourceViewHashProvider` даёт версионный хеш, чтобы биндинг не дёргался вхолостую.
- Инструменты: Unity Profiler с UI Toolkit-маркерами; Frame Debugger (draw call'ы и батчи); UI Toolkit Debugger (`Window > UI Toolkit > Debugger`); `PanelSettings.SetPanelChangeReceiver(IDebugPanelChangeReceiver)` — логирует, какой элемент и почему изменился (редактор и dev-билды).
- Улучшения Unity 6: диспетчеризация событий вдвое быстрее, генерация геометрии в Job'ах, Vector API на нативной реализации, распараллеленная генерация текста, публичный Custom Geometry API, кеширование лэйаута для глубоких иерархий.

## 11. Текст: TextMeshPro, TextCore, ATG

- **TextMeshPro и UI Toolkit — разные системы.** В UI Toolkit нет и не планируется компонента TMP. Пакет `com.unity.textmeshpro` объявлен устаревшим и влит в `com.unity.ugui`; TMP остаётся текстом для uGUI.
- UI Toolkit использует **TextCore** (SDF-рендер, исторически основан на TMP), а поверх него — **ATG** (Advanced Text Generator) на HarfBuzz + ICU + FreeType.
- Хронология ATG: opt-in в 6.0 → умолчание в редакторе с 6.3 → IMGUI в 6.4 → рантайм UI Toolkit в 6.5. **Все фичи ATG из 6.5 забэкпорчены в 6.3**, Unity прямо рекомендует включать. Прирост CPU 10–40 %, рендер не меняется визуально.
- Включение: `Edit > Project Settings > UI Toolkit > Enable Advanced Text Generator`, затем в USS `:root { -unity-text-generator: advanced; }` (наследуется вниз).
- Ограничения ATG: не поддерживает static font assets (нужна миграция), нельзя править метрики глифов.
- Миграция uGUI на ATG нацелена на 6.8 — нас не касается, uGUI мы не используем.
- Для наших цифр HUD: моноширинный шрифт или `-unity-font-definition` с фиксированной шириной цифр, иначе стрелка спидометра будет дёргать вёрстку при смене «1» на «8».

## 12. Антипаттерны

**Из эпохи uGUI, вредные здесь:**

- «Сделай спидометр из `Image` с `type = Filled` и радиальной заливкой». Работает, но требует нарезки спрайтов, атласа и не даёт нормального сглаживания. В 6.3 есть Painter2D и SVG.
- «Положи весь UI на один Canvas» / «раздели Canvas'ы». Это оптимизация **uGUI** под перестроение Canvas. В UI Toolkit понятия «canvas rebuild» нет вообще, зато есть vertex budget и лимит 8 текстур — оптимизировать нужно другое.
- «Выключай `Raycast Target`», «убирай `Graphic Raycaster`». Тоже про uGUI. В UI Toolkit аналог — `pickingMode = PickingMode.Ignore` на декоративных элементах.
- «Анимируй UI через `Animator`». Аниматор пачкает элементы каждый кадр, даже если значение не изменилось. В UI Toolkit его нет и не надо.
- «Не забудь `Screen Space - Camera`». У `PanelSettings` таких режимов нет: только `Screen Space Overlay` и `World Space`.

**Из ранних гайдов по UI Toolkit (2021–2023), уже неверные:**

- `UxmlFactory` / `UxmlTraits` для кастомных контролов — устарели в Unity 6, будут удалены. Только `[UxmlElement]` + `[UxmlAttribute]`, класс обязан быть `partial`.
- «Data binding есть только в редакторе» — рантайм-биндинг появился в Unity 6.
- «World-space UI на UI Toolkit невозможен» — появился в 6.2.
- «Добавь в сцену `EventSystem`, иначе UI Toolkit не получит ввод» — не нужно, если нет uGUI; добавление `EventSystem` наоборот переключает UI Toolkit на мостовые компоненты.

**Свои, которые легко допустить:**

- `label.text = $"{speed:F0} км/ч"` в `Update` — строка создаётся каждый кадр, мусор GC превращается в фризы.
- `root.Q<Label>("speed")` в `Update` — поиск по дереву в горячем пути. Кешировать в `OnEnable` (официальные примеры делают запросы именно там). И помнить: при опечатке в имени `Q<>()` вернёт `null`, а NRE прилетит позже и в другом месте.
- Отдельная `PanelSettings` на каждый элемент HUD. Несколько `UIDocument` должны ссылаться на **одну** `PanelSettings` — это документированная оптимизация.
- Биндинг в режиме `TwoWay` (умолчание) на read-only дисплеях — лишний поток данных.
- Скругления и вложенные маски ради красоты: каждый уровень стенсила рвёт батч, глубина ограничена семью.
- `opacity: 0` вместо `display: none` для скрытого HUD — элемент рендерится и создаёт overdraw.

## 13. Чек-лист

**Настройка проекта**
- [ ] `Active Input Handling = Input System Package (New)`.
- [ ] `Edit > Project Settings > UI Toolkit` → включён Advanced Text Generator.
- [ ] Одна `PanelSettings` для HUD: `Scale With Screen Size`, 1920×1080, Match 0.5.
- [ ] Отдельная `PanelSettings` для отладочного оверлея с бо́льшим `Sort Order` и `Constant Pixel Size`.
- [ ] В коммит попали `.uxml`, `.uss`, `.asset` и все `.meta`.

**Код**
- [ ] Все `Q<>()` — в `OnEnable`, результаты в полях; имена — в `const string`.
- [ ] Кастомные контролы — `[UxmlElement] public partial class`, атрибуты — `[UxmlAttribute]`.
- [ ] Свойства источников данных — `[CreateProperty]`; тип — `[GeneratePropertyBag]`.
- [ ] Биндинги дисплеев — `BindingMode.ToTarget`.
- [ ] Ни одной интерполяции строк в `Update`; текст меняется только при смене целого значения.
- [ ] Анимируется `translate` / `scale` / `rotate`, не `width` / `top`.
- [ ] `usageHints` выставлены до добавления элемента в панель.
- [ ] Редкие панели снимаются `RemoveFromHierarchy()`, частые — `display: none`.

**Проверка**
- [ ] Frame Debugger: HUD укладывается в 1–2 draw call'а; если нет — считать текстуры (лимит 8) и поднять Vertex Budget.
- [ ] Profiler: нет GC-аллокаций в кадре при езде.
- [ ] UI Toolkit Debugger: нет неожиданных пересчётов лэйаута.
- [ ] HUD не разъезжается на 16:10, 21:9 и 1280×720.
- [ ] Геймпад: по меню настроек можно пройти стиками и D-pad, `Submit`/`Cancel` работают.
