# Автоматизация редактора: сцена как код

Детали — [docs/unity/16-ai-tooling.md](../../../docs/unity/16-ai-tooling.md).

## Главное правило

**Источник правды для сцены — наш C# Editor-код, а не файл `.unity`.** Файлы `.unity`
и `.prefab` — это YAML со ссылками по GUID; править их руками ненадёжно, а сливать
при конфликте почти невозможно.

Отсюда:

1. Расстановка объектов, дорог, света, трафика делается классом-строителем
   в `Assets/_Project/Scripts/Editor/`, который можно запустить заново и получить ту же сцену.
2. Префабы и ScriptableObject-ассеты создаются кодом через `PrefabUtility` и
   `AssetDatabase`, а не перетаскиванием мышью, где это разумно.
3. Запуск из терминала: `-batchmode -executeMethod Namespace.Class.Method`.
4. Там, где ручная работа в редакторе неизбежна, агент даёт пользователю **пошаговую
   инструкцию, что кликнуть**, а не молча правит YAML.

## Чего не делать

- Не редактировать `.unity` и `.prefab` текстовыми правками.
- Не запускать Unity в batch-режиме, пока проект открыт в редакторе: проект залочен.
- Не заявлять, что сцена собралась, не проверив лог запуска.
